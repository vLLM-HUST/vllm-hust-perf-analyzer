# Repo Knowledge

Use this Skill as the repository's single agent-facing knowledge and capability
entrypoint. Repository instructions and source remain authoritative; this tree
preserves only the additional leverage that real work has earned.

## Enter through the catalog

1. Read [`CATALOG.md`](CATALOG.md) before substantive repository work and
   before re-deriving repository-specific knowledge or rerunning an experiment.
2. Choose the scenario whose stated use condition matches the current task,
   question, or uncertainty, then read its `GUIDE.md` completely.
3. Use that scenario's accepted understanding, bounded observations,
   instructions, checks, fixtures, and executable helpers directly when
   present.
4. If no repository scenario matches, follow repository authority and source,
   or run the smallest useful experiment. Do not create a scenario merely to
   fill the tree.
5. When work has earned reusable understanding, an expensive observation,
   capability, or another form of repository leverage—or this tree needs to
   change—read
   [`scenarios/grow-repo-knowledge/GUIDE.md`](scenarios/grow-repo-knowledge/GUIDE.md)
   before editing the knowledge plane.

Once planted, this tree is sovereign local state. Do not depend on a global
seed Skill, synchronize from a central template, or accept overwrite as an
upgrade mechanism. Keep the tree cheaper than rediscovery and let Fletcher own
long-horizon curation.
